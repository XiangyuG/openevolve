program run, with the result still provably equivalent to the original. Make any
change you can justify as preserving the program's observable behavior (its
return value and its final map state for every input). Useful directions, not a
closed list:

Every change needs the Example line and the Witness line. The two Formula lines
are a machine-checkable proof and only carry information for a WIDTH-NARROWING
change (a map value struct, a hash map key type, or a scalar variable getting
fewer bytes/bits). For any other change -- hoisting a lookup, dropping a dead
store, tightening a loop bound, a pure refactor -- write exactly:
    Formula (pre-transformation): (assert true)
    Formula (post-transformation): (assert true)

When you DO write real formulas, each is a self-contained SMT-LIB 2 script. The
pre one has a `(declare-const ...)` for every input the change depends on and a
constant named exactly `pre_result` asserted equal to what the OLD code computes
for this change; the post one re-declares the SAME input names and sorts plus
`post_result` for the NEW code. They are checked by proving
`(assert (not (= pre_result post_result)))` UNSAT against both combined -- equal
for EVERY input, not just some. Model only the values this change touches. Use
only Int and Bool sorts; do NOT use BitVec constants or bitvector operators
(bvand, bvor, ...) -- approximate a bitwise mask with `mod` (e.g.
`(= (mod mode 8) 0)` for a low-bit check). No triple-backtick fence around a
formula, and nothing after its final `)`.

Then add AT MOST ONE of the following tag lines, directly after the
post-transformation formula, and only when it exactly describes this change --
omit all three otherwise:

  Map value width change: <map_name>: <old_bytes> -> <new_bytes>
      -- this change shrank that map's VALUE struct.

  Map key width change: <map_name>: <old_bytes> -> <new_bytes> key <ctx_field> < <bound>
      -- this change shrank that hash map's KEY type. The "key <ctx_field> <
      <bound>" clause is REQUIRED: <ctx_field> is the BPF context field the key
      is derived from (e.g. rx_queue_index, cpu, common_pid) and <bound> is the
      exclusive limit it never reaches (e.g. 65536 for a narrow to 2 bytes).
      Your formulas MUST also prove it: assert `(< <ctx_field> <bound>)` on the
      shared input in the pre-transformation formula and model the post one as
      truncation (e.g. `(assert (= post_result (mod k 65536)))`).

  Variable width change: <var_name>: <old_bits> -> <new_bits>
      -- this change narrowed a scalar VARIABLE from a proven range invariant.
      Assert the range on the shared input in the pre-transformation formula
      and model the post one as truncation (e.g.
      `(assert (= post_result (mod v 16)))` for an unsigned narrow to 4 bits).

Each "Example" line must quote a real, short fragment (a line or part of a line)
